A private tracker that is yours, not rented.

TorrentTrader is a complete private BitTorrent tracker — announce, ratio accounting, forums, invites, moderation and an admin panel — that you run on your own machine. It is free, the source is public, and forking it to build something else is the point rather than a loophole.

What it is

The classic tracker, rebuilt properly

A lot of small communities were built on the original PHP TorrentTrader. It worked, then it stopped being maintained, and what was left was a decade of hand-applied mods on top of code nobody wanted to touch. This is that idea rewritten from nothing: a Go backend, a React frontend, and a real test suite.

It is finished software, not a foundation you have to complete. The list below is what ships today, not a roadmap.

Included

Tracker

Announce and scrape

Passkey-authenticated HTTP announce with per-user ratio accounting, freeleech and half-credit torrents, configurable peer limits and download wait times, and an append-only announce log.

Anti-cheat

Detection that files itself

Impossible upload speeds, upload reported with no downloaders, and left values that disagree with the transfer — each raises a flag into one staff queue, off the announce hot path.

Content

Uploads and discovery

Per-category metadata schemas, full-text search, comments and ratings, an RSS builder, a live release stream, and a moderation queue staff can claim from.

Community

Forums, chat, messages

Forums with moderation and edit history, a WebSocket shoutbox, private messages with threads, drafts and templates, and @mentions that notify the right person.

Membership

It runs itself

Invite trees with optional automatic distribution, classes with per-capability permissions, promotion and demotion on ratio and seeding thresholds, and warnings that escalate to restrictions and bans without staff intervention.

Economy

Bonus points

Points earned by seeding, an append-only ledger recording every movement, and a store that spends them. Off by default — switch it on only if you want one.

Announcements

Tell people what landed

New uploads can be pushed to Discord, Telegram, IRC, a webhook, the shoutbox, or a live feed — each with its own category filters, size floor and message template.

Data

Members can see their own record

Every announce a client makes is logged with what it transferred, and each member can read their own log from their profile — which settles most ratio arguments without a staff ticket. No IP addresses are kept. Raw records expire on a retention window you set; monthly transfer totals are compiled before they go and kept for good.

Operations

An admin panel over all of it

Every system above has a screen. Torrents can be looked up by info hash — the identifier a takedown notice actually gives you — and banned, unbanned or deleted in batches, with each one logged separately so you can still answer "who banned this, and when". Plus an activity log that keeps staff-only entries away from members, database backups, and roughly forty settings you can change without a deploy.

Your site, your rules

Turn off the parts you do not want

Not every community wants an economy, or automatic promotions, or outbound announcements. Almost every subsystem here has a switch in the admin panel, and turning one off removes it from the site rather than leaving a dead menu item.

See every setting, including what each one defaults to.

For people who script things

The web UI is just one client

Everything the interface does goes through a documented REST API, and members are welcome to build their own tools against it. The published contract is an OpenAPI document describing the member-facing surface; administrative endpoints are deliberately kept out of it.

The tracker also exposes a passkey-authenticated RSS feed, so a client can watch for new releases without anyone writing code at all.

There is a command-line tool, tt, for driving a site from a terminal. It talks to the same REST API, so it does nothing the web interface cannot — the point is that a cron job, a shell pipeline, or an operator on a box with no browser can use it. It keeps a named profile per site, holds tokens in a file only you can read, and prints either a readable table or JSON for scripts to parse. It logs in with your username and password and renews its own token afterwards, so a scheduled job keeps running without anyone typing a password into it. It ships as a binary alongside the server in each release.

The deal

Free, open, and yours to change

It costs nothing. There is no paid tier, no hosted edition, no feature held back for a licence. Download it and run it. The licence is MIT — about as short and permissive as licences get.

Forking is encouraged. Take it, rename it, rip out half of it, build the tracker your community actually wants. You do not need permission and you do not owe anything back. Communities are different from each other, and a project that expects everyone to run the same thing is not serving them.

Contributions are genuinely appreciated. Bug reports, fixes, features, documentation, a translation, a note that something is confusing — all of it makes the project better for the next person. An issue is usually the fastest way to start.
