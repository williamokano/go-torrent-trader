Configure

Decide what your site actually is

Most of TorrentTrader can be switched off. Every setting below lives in Admin → Settings and takes effect immediately — no restart, no deploy, no editing a file on the server.

Two kinds of configuration

Settings and environment

Settings are the ones on this page. They are stored in the database, changed from the admin panel, and are about how your community behaves.

Environment variables are set in stack.env before the server starts — database credentials, SMTP, storage, your site name and URL. Those are on the install page. If you find yourself wanting to restart the server to change a rule, you are probably looking in the wrong place.

Who gets in

Registration

Setting Default What it does
registration_mode invite only open lets anyone sign up; invite_only requires an invite from an existing member. Invites are the private-tracker default for a reason — they make the invite tree a moderation tool.

The tracker itself

Peers and wait times

Setting Default What it does
tracker_max_peers_per_torrent — Caps how many peers one torrent may hold. Protects the tracker from a single enormous swarm.
tracker_max_peers_per_user — Caps concurrent connections per member — the usual defence against one account being shared around.
wait_time_enabled off Makes new torrents unavailable to low-ratio members for a period, so the people who seed get first access.
wait_time_tiers — How long each ratio band waits.
wait_time_bypass_ratio — The ratio above which a member never waits.

Cheating

Detection

Checks run off the announce path, so they never slow a client down, and everything they find lands in one staff queue rather than several.

Setting Default What it does
cheat_detection_enabled on The master switch for all three checks below.
cheat_max_upload_speed_mb_s 100 Flags a member reporting an upload rate no real connection could produce.
cheat_left_mismatch_tolerance_pct — Flags a client whose reported remaining bytes disagree with what it says it transferred.
cheat_flag_cooldown_hours 6 Stops one misbehaving client from filling the queue with the same flag repeatedly.

A third check — upload reported while nobody was downloading — needs no configuration.

Membership

Promotion, invites and warnings

Setting Default What it does
promotion_enabled off Promotes and demotes members between classes automatically on ratio and seeding thresholds you define per class. Staff classes are never touched.
promotion_interval_days — How often the engine runs.
promotion_seed_window_days — How far back seeding history counts.
invite_distribution_enabled off Hands out invites to eligible classes on a schedule, up to each member's ceiling, instead of doing it by hand.
invite_distribution_interval_days — How often invites are granted.
warning_escalation_enabled off Escalates repeat warnings into a restriction and then a ban without staff having to track counts.
warning_count_restrict — Warnings before a privilege is restricted.
warning_count_ban — Warnings before an account is banned.
warning_restrict_type — Which privilege the restriction removes.
warning_restrict_days — How long it lasts.

Economy

Bonus points

Off by default. Turn it on only if you want members earning points for seeding and spending them in a store — plenty of communities are happier without one.

Setting Default What it does
bonus_enabled off Awards points hourly and reveals the store. Every movement is written to a ledger, so a balance can always be explained.
bonus_points_per_seeding_torrent 1 Points per seeding torrent, per award run.

Enforcement

Hit-and-run

Off by default. Tracking only ever starts from the moment this is turned on — nothing already snatched is retroactively tracked.

Setting Default What it does
hnr_enabled off Starts a tracked seed obligation on every completed download, per the per-class rules on the Hit-and-Run admin page.
hnr_seed_credit_cap_minutes 45 The anti-gaming guard. A gap between two seeding announces longer than this earns zero credit for that gap, so seed time can only be earned by actually announcing continuously.
hnr_grace_after_complete_hours — How long after a snatch completes before it is evaluated at all, giving a member time to start seeding before any clock that matters begins.
hnr_retention_days 180 How long a resolved record (satisfied, cleared, or waived) is kept before it is purged. 0 keeps resolved records forever.
hnr_exempt_donors off Whether donor accounts are exempt from tracking entirely.
hnr_clear_pricing_mode fixed How clearing an obligation with bonus points is priced: a fixed price by torrent size, or a price proportional to the upload still needed to reach the required ratio.
hnr_clear_base_points 50 Flat component of the fixed clear price.
hnr_clear_points_per_gib 10 Added to the base price for every GiB of the torrent's size, under fixed pricing.
hnr_clear_points_per_gib_deficit 25 Price per GiB of upload still needed to reach the required ratio, under deficit pricing.

Moderation and chat

Uploads and the shoutbox

Setting Default What it does
moderation_enabled off Holds new uploads in a queue for staff approval instead of publishing them immediately.
moderation_public_visibility — Whether members can see what is waiting in the queue.
chat_rate_limit_max — Messages allowed inside the window.
chat_rate_limit_window — Length of that window.
chat_rate_limit_message — What a member sees when they hit it.
chat_spam_strike_count — Strikes before an automatic mute.
chat_strike_reset_seconds — How quickly strikes decay.
chat_spam_mute_minutes — How long the automatic mute lasts.
chat_spam_mute_message — What the muted member is told.
chat_system_display_name — The author name on automated shoutbox posts, such as new-upload announcements.

Outbound

Announcements to other services

Setting Default What it does
connectors_enabled off The master switch for pushing new uploads to Discord, Telegram, IRC, a webhook, the shoutbox or a live feed. Each destination is configured separately with its own filters and template, so you can announce films to one channel and music to another.
connectors_allow_private_networks off Permits webhooks pointing at private addresses. Leave it off unless you are deliberately posting to something on your own network — it exists to stop a webhook being used to probe your internal services.
connector_delivery_retention_days 30 How long delivery history is kept for troubleshooting.

Data

The announce log

Setting Default What it does
announce_log_enabled on Records every announce with its transfer deltas. This is what makes accurate seeding statistics and better cheat detection possible later.
announce_log_retention_days 90 The shortest time individual announce records are kept. A nightly job totals each day into permanent per-member monthly figures and then deletes the raw rows past this window, so the log stops growing without losing anyone's transfer history. Treat it as a floor rather than a promise: features that read raw announces hold the window open for as long as they need it, and automatic class promotion does once you switch it on — 31 days at its default seeding window. Admin → Settings tells you when the value you saved is not the one in force. It does not give disk back either — once autovacuum has swept them, the deleted rows' space is reused by later announces rather than returned to the filesystem. Only VACUUM FULL shrinks the database itself, and it locks the table while it runs and needs the table's size again in free space. Set it to 0 to keep every raw announce indefinitely.

Know what you are storing. The announce log records what each member's client transferred and when, identified by peer ID. It deliberately holds no IP addresses: the tracker needs a peer's address to answer an announce and keeps it only while that peer is in the swarm, so there is no months-long history of anyone's address to leak or to hand over. Members and staff can read the log from a member's profile, and the monthly totals stay readable after the raw rows are gone.

The indexes look after themselves. The nightly prune holds the log's row count steady and the space it frees inside the table gets reused, but the indexes are a different matter: they are ordered by time and by id, and the prune always removes the oldest rows, so the freed pages collect at one end while every new announce is added at the other. Left alone they would grow without limit, well past what the row count suggests. TorrentTrader rebuilds them on the first of each month, at 01:00, and there is nothing for you to configure or run yourself. Members keep announcing throughout — the rebuild deliberately never takes a lock that would stop them, apart from a moment as it swaps each finished index in. Two things are worth knowing before it first runs on a large site: it needs as much free disk as the announce log's indexes currently occupy, because it builds the replacements alongside the originals; and while it runs, routine vacuuming is held back, so pick a quiet hour if you move it.

Not enough knobs?

Then change it

TorrentTrader is MIT licensed and free of charge. If a setting you want does not exist, the code is right there — fork it and add it. Running a modified version is the spirit of this project, not an edge case.

And if the setting seems generally useful, an issue describing what you needed is genuinely valuable, whether or not you write the code yourself.
